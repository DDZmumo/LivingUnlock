# LivingUnlock 0.2.4（实验版）

Windows 和 Android 统一版本号为 0.2.4。

这次重点更新蓝牙连接方式和安卓设置，同时修复 Windows 配对提示、完善旧配对兼容，并调整客户端背景亮度。

## 蓝牙解锁

- 电脑优先主动连接已配对手机，手机被动监听，解决本次实测中 HyperOS 熄屏暂停 BLE 扫描导致收不到请求的问题。
- 移除手机持续重连：仅响应连接事件或电脑上的“再次发送”，仍需指纹确认和原有挑战校验。
- 修复 Windows BLE 广播启动失败；兼容回退使用带请求编号的广播，同一编号去重处理。
- 手机只在处理已配对电脑的连入请求时短暂持有唤醒锁，空闲时不持有。

### 连接方式有什么变化

| 场景 | 本版行为 |
| --- | --- |
| 默认设置 | 电脑主动连接手机；手机被动监听，BLE 兼容扫描关闭。 |
| 手动开启 BLE 兼容扫描 | 手机同时保留被动监听和 BLE 扫描；电脑直连失败时可广播，手机发现后再连接。 |
| 手机无法连接 | 一次主动连接有超时和取消边界，不循环连接；可在电脑点击“再次发送”。 |
| 电脑重复发送 | 旧挑战仍按原有状态机失效；兼容广播使用新编号，同一编号不会反复触发连接。 |
| 关闭安卓解锁监听 | 被动监听和兼容扫描都停止，保留绑定数据。 |

两种连接路径均使用本地蓝牙，不依赖互联网。手机仍只完成生物识别签名，不接收 Windows 密码。

## Android

- 新增设置页，主页右上角齿轮可进入“蓝牙连接”。
- 提供解锁监听总开关、默认关闭的 BLE 兼容扫描开关，以及连接方式和旧配对迁移说明。
- 开关即时生效并保存；关闭兼容扫描后保留被动监听。
- Compact APK 继续使用原有正式签名和包名；versionCode 增至 4。
- 设置页沿用角色背景、深蓝卡片和淡蓝描边；长说明可滚动，返回主页和切回解锁请求保持可用。
- 兼容扫描的偏好单独保存。监听总开关关闭时，即使兼容扫描偏好为开启，也不会实际扫描；重新启动应用后恢复已保存的选择。
- 修复阻塞式蓝牙连接无法及时响应协程取消的问题；超时或取消会关闭对应连接。
- 监听服务处理蓝牙开关变化：关闭蓝牙时清理连接和监听，重新开启后按保存的设置恢复。

## Windows

- 已绑定手机时隐藏配对二维码，提示先解除绑定，避免重复配对。
- 进入配对页面和刷新二维码均先检查已有绑定；对系统保护目录中的绑定状态保留提权查询路径。
- 未收到配对请求就断开连接时，显示取消状态，不再把它误报为配对失败。
- 配对取消后隐藏失效二维码并停止倒计时，允许用户重新发起配对；未收到有效配对请求时不写入新绑定。
- 提亮管理客户端背景与首页角色图片。
- 客户端及管理工具兼容新版配对地址记录，原生 Windows Hello PIN 和密码登录保持可用。
- 新配对保存实际蓝牙连接中的手机地址；旧配对只有在签名、请求状态和有效期校验通过后才补充地址，不依据设备名称选择手机。

## 升级与回退

1. 同时更新 Windows Setup 与 Android Compact。
2. 旧配对若尚未启用主动连接，在手机设置中临时开启 BLE 兼容扫描，保持手机亮屏并完成一次指纹解锁。电脑只在验证成功后记录手机地址，之后即可关闭兼容扫描，无需重绑。
3. 新版重新配对会直接记录手机地址。

Debug 与正式 Compact 的包名、配对数据相互独立；从 Debug 切换到正式版仍需重新配对，并关闭旧版监听。

升级后的配对记录为 v2，旧版 Windows 不识别。回退需恢复升级前备份或重新绑定。Windows 登录组件被占用时，安装程序可能需要重启完成替换。

## 验证与限制

- 本次全新构建 Windows 登录组件、配对工具、WinUI 客户端及 Setup，安装包版本为 0.2.4.0。
- 本次 Compact 的代码和资源裁剪构建成功；确认版本为 0.2.4 / versionCode 4，APK 签名验证通过，证书与上一正式版一致。
- 针对配对记录兼容与迁移、连接取消、登录组件重发和字段状态执行了最小范围检查。
- 用户已在 Xiaomi 17 Pro / HyperOS 4 上确认新版主动连接的亮屏和熄屏指纹解锁可用。
- Android 设置页已在手机检查；兼容扫描开启、关闭和重启后保存正常，关闭后系统不再注册该扫描，被动监听仍在运行。
- 上述手机功能验收使用 Debug 包；本次正式 Compact 包另行验证构建、版本与签名，不代表所有手机和长期待机环境均已验收。尚未量化耗电。
- BLE 回退仍受系统熄屏扫描限制；需保持手机解锁监听和蓝牙开启。
